# TheRuinForge

TheRuinForge is a single-file Node.js application: its Roblox Luau script-builder page and server-side Discord OAuth login with required Discord server membership check are both in `server.js`.

## Requirements

- Node.js 18 or newer
- A Discord application in the Discord Developer Portal
- A Discord bot added to your community server
- Your Discord application client ID and client secret
- Your Discord server (guild) ID

## Run locally

1. In the project folder, copy `.env.example` to `.env`.
2. In Discord Developer Portal, open your application and add this exact OAuth2 redirect URL:
   `http://localhost:3000/auth/discord/callback`
3. Fill in the `.env` values. The bot must be in the server whose ID is `DISCORD_GUILD_ID`.
4. In a terminal, run:
   ```sh
   npm install
   npm start
   ```
5. Open `http://localhost:3000`.

The application code is in `server.js`. Keep `package.json` and `package-lock.json` for Node.js dependencies. `.env.example` is a local configuration template; `.env` is private and must never be uploaded to GitHub.

## Deploy on Render with a GitHub repository

1. Download and extract `Ruinforge-deploy.zip`.
2. Create a **new, empty GitHub repository** and upload the extracted project files. Do not upload `.env`, `.env.rtf`, `node_modules`, or the ZIP itself. The `.gitignore` file excludes private environment files and dependencies.
3. In Render, choose **New > Blueprint**, connect that GitHub repository, and deploy the `render.yaml` Blueprint. Render builds the app with `npm ci` and starts it with `npm start`.
4. After Render creates the service, copy its public URL, such as `https://your-service.onrender.com`.
5. In the Discord Developer Portal, add this exact OAuth2 redirect URL to the application:
   `https://your-service.onrender.com/auth/discord/callback`
6. In the Render service's **Environment** settings, set `DISCORD_REDIRECT_URI` to that same URL. Set `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_GUILD_ID`, and `DISCORD_BOT_TOKEN` there as well. `SESSION_SECRET` is generated by the Blueprint. Save changes and redeploy.
7. Open the Render service URL. To use a custom domain, add it under the service's **Settings > Custom Domains** and follow Render's DNS instructions; update the Discord redirect URL to use that domain too.

The `DISCORD_REDIRECT_URI` must exactly match the URL registered in Discord. Do not put Discord secrets in GitHub or in browser code.

> **Important:** The original project Git history contains tracked `.env` files. Use the new empty GitHub repository and the clean ZIP contents above; do not push the original repository's Git history. If its secrets have already been pushed to a remote, rotate the Discord client secret and bot token before deploying.

## How the gate works

- The login button redirects users to Discord's official OAuth2 authorization page.
- The backend validates the OAuth state and exchanges the code using the client secret, which stays server-side.
- The backend uses the bot token to check whether the signed-in Discord user belongs to the configured server.
- The script-builder UI remains covered until the backend reports both authentication and membership.
- Users who are not members see the invite link and can retry the membership check after joining.

The required invite link is set to: https://discord.gg/83wsqggMK

## Security notes

- Never put `DISCORD_CLIENT_SECRET`, `DISCORD_BOT_TOKEN`, or `SESSION_SECRET` in browser JavaScript or commit your `.env` file.
- Use HTTPS and set `NODE_ENV=production` when deployed. Configure `DISCORD_REDIRECT_URI` to your exact HTTPS callback URL.
- The included Express session uses the default in-memory session store. It is okay for local testing but should be replaced with a persistent session store for production deployments.
- A Discord bot token can access the server API as that bot. Keep it private and rotate it immediately if exposed.
- The front-end gate is only UI. Any protected API or server-side data must also enforce authentication and membership on the backend.
- This is a starting project, not a deployed website. The OAuth app, bot, environment variables, and hosting must be configured before login can succeed.

## Troubleshooting

- **Login immediately errors:** check every `.env` value and ensure the callback URL exactly matches the one registered in Discord Developer Portal.
- **Membership always fails:** ensure the bot is in the target server and `DISCORD_GUILD_ID` is the server ID, not an invite code.
- **It says verification is not configured:** `.env` is missing or one of the required values is blank.
